What is this environment?

CareOtter is a vulnerable IoT healthcare device simulator for security testing and learning. The lab reproduces a modern cardiac implantable electronic device similar to an ICD (Implantable Cardioverter-Defibrillator) — a sophisticated computer that manages autonomous heart rhythm control.

Modern ICDs have evolved from simple arrhythmia extinguishers into cardiac computers managing life-or-death events in milliseconds. Like a pacemaker, they maintain a marked rhythm when the heart weakens, and deliver electric shocks on critical arrhythmia.

VulnZoo WWW interface — device management, loading/stopping the CareOtter simulator, and project administration.

CareOtter device interface — the actual vulnerable IoT device with BLE services, web panel, and API endpoints. This is where you perform penetration testing.

Device architecture

  • BLE — GATT services for continuous heart rate and SpO₂ monitoring, interacting with mobile apps and wearables.
  • Cloud API — backend gateway bridging the binary device protocol to REST, enabling remote monitoring and clinician dashboards.
  • Web interface — embedded dashboard with real-time cardiac telemetry, device status, and admin controls.
  • Data storage — persistent telemetry logs and configuration data.
  • Mobile app — Android companion connecting via both BLE and the cloud API.

Security training focus

CareOtter supports multiple security profiles via idempotent hooks that reconfigure the device without code changes.

  • Phase 1 — Secure. Baseline secure configuration with all protections enabled.
  • Phase 2 — Wireless. Relaxed BLE controls for wireless attack surface practice.
  • Phase 3 — Network. Weakened cloud and API protections for network attacks.
  • Phase 4 — Data. Reduced storage and logging protections for data extraction.
