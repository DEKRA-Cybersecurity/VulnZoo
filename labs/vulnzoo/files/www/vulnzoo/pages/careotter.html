What is this environment?

CareOtter is a vulnerable IoT healthcare device simulator designed for security testing and learning. This lab reproduces a cardiac monitoring system with Bluetooth Low Energy (BLE) connectivity, cloud synchronization, and mobile application integration. The device monitors heart rate data and transmits it to a cloud API for remote patient monitoring.

VulnZoo WWW Interface: Used for device management, loading/stopping the CareOtter simulator, and project administration.

CareOtter Device Interface: The actual vulnerable IoT device with BLE services, web panel, and API endpoints - this is where you perform penetration testing on medical IoT vulnerabilities.

The simulator allows you to practice pentesting techniques on medical IoT devices, including BLE sniffing and MITM attacks, API authentication bypass, cloud synchronization vulnerabilities, and data storage exploitation. CareOtter includes multiple security profiles (Phase 1-4) that progressively disable security controls to simulate different attack scenarios.

Security Training Phases

CareOtter supports multiple security profiles for different training scenarios:

  • Phase 1 (Secure): All security protections enabled - baseline secure configuration
  • Phase 2 (BLE Vulnerabilities): Bluetooth encryption disabled, no pairing authentication - practice wireless attacks
  • Phase 3 (API Vulnerabilities): OAuth2 downgraded to basic auth, certificate pinning disabled - practice cloud API attacks
  • Phase 4 (Storage Vulnerabilities): Database encryption disabled, PII exposed in logs - practice data extraction

Each phase is managed through idempotent hooks that reconfigure the device without requiring code changes.

Attack Vectors

When CareOtter is loaded, you can explore vulnerabilities across multiple attack surfaces:

  • BLE Communication: Sniff unencrypted heart rate data, perform MITM attacks, inject malicious commands
  • Cloud API: Bypass authentication, intercept authorization codes, replay tokens, access other patients' data
  • Web Interface: Exploit XSS, CSRF, insecure direct object references in the device dashboard
  • Data Storage: Extract SQLite database, analyze plaintext PII in logs, recover deleted records
  • Mobile App: Reverse engineer APK, extract hardcoded credentials, bypass certificate pinning
